# portfolio-manager-sample

ポートフォリオ管理 / 底値分析ダッシュボード（Streamlit・サイバーパンク配色）。

担保=配当4銘柄、被担保=日産自動車。担保増価による LTV 余力と、
担保プールの底値ストレステストを可視化します。

> ⚠️ サンプルデータです。銘柄・株数・借入額などはすべてサンプル値で、投資助言ではありません。

## ページ

サイドバーで切り替える3ページ構成（`st.navigation`）。

| ページ | 内容 |
|---|---|
| 📊 **ポートフォリオ管理** | 保有銘柄と含み損益、LTV バンド表示 / 70%枠余力 / NAV、しきい値（60/70/85%）進捗と抵触までの距離 |
| 📉 **底値分析** | 担保プールの底値ストレステスト、銘柄別 底値マップ、日産 買い増しラダー |
| 📚 **資料** | 日産分析ノート・記事へのリンク（GitHub Pages） |

現値の更新時刻と「🔄 再取得」はサイドバーに集約。日産評価額・現金バッファは
expander に畳んでいます。

しきい値バンドは「超えた線」ではなく「次に向かう線」の色で示します（60%超過なら次は70%警告なので 🟡）。含み損益は `portfolio.py` の `avg_cost` を
登録した銘柄だけが集計対象です。

## 底値分析の考え方

「単一銘柄が◯円以下だった日数」ではなく、**このポートフォリオの借入と担保構成に
紐づけて**底値を評価する:

1. **担保プール 底値ストレステスト** — 現在の保有株数を過去の日足に当てはめて
   担保プールの合成日次系列を作り、現在の借入残高に対する LTV しきい値
   （60/70/85%）の抵触水準・抵触日数・最長連続日数・直近抵触日を出す。
   終値ベースの最大ドローダウン、推移チャート、日次系列の CSV 出力つき。
2. **銘柄別 底値マップ** — 期間安値／高値と現値の位置関係、および
   「期間安値から +X% 以内で寄り付いた取引日数」（＝その水準を拾う機会が
   実際に何日あったか）。
3. **日産 買い増しラダー** — 年1,000万の買い増しペースを前提に、指値水準ごとの
   到達日数・到達率・最長連続取引日数・直近到達日と、1,000万で買える株数。

日数はすべて**取引日**ベース（暦日ではない）。判定にはその日の**安値**を使う。
担保プールは1銘柄でも日足が欠けた日を混ぜると評価額が過小になるため、
全銘柄が揃った共通営業日のみを対象にする。

> 着想のきっかけ: [mokusei02/stock-bottom-days-checker](https://github.com/mokusei02/stock-bottom-days-checker)
> （指定金額以下だった連続期間を数えるアプリ）。
> 本ページは「担保プール × LTV しきい値」という別の問題設定に組み替えた
> 独自実装で、コードの流用はしていません。

## 構成

```
app.py                 ルーター (st.navigation) + テーマ注入
theme.py               配色と筐体CSS                 ← 表示専用
skyline.py             保有銘柄のSVGスカイライン生成   ← streamlit / 通信 非依存
portfolio.py           保有銘柄・借入の定義と集計    ← streamlit 非依存
bottom_analysis.py     底値分析の計算                ← streamlit / 通信 非依存
market.py              Yahoo Finance 取得 (キャッシュ)
ui.py                  ページ共通の表示ヘルパー
views/                 ページ本体 (portfolio / bottom / notes)
tests/                 純関数の単体テスト
```

数字の出どころ（`portfolio.py` / `bottom_analysis.py`）と表示（`views/`）を分けて
あるため、計算はネットワークなしで検証できます。

## 株価データ

Yahoo Finance の chart API を使用（追加パッケージ不要、`requests` のみ）。

- **現値**: 保有5銘柄（`<コード>.T`）の `regularMarketPrice` を15分キャッシュ。
  取得失敗時は `portfolio.py` 内の `fallback_price` に自動フォールバック。
- **日足**: 同エンドポイントに `range` / `interval=1d` を付けて OHLC を取得、
  1時間キャッシュ。底値分析ページのトグルを ON にしたときだけ取得する。

Yahoo Finance は海外サーバーからでも日本株の当日終値を返すため、
Streamlit Community Cloud 上でも株価が反映されます。

## 配色

**ダーク専用**（ライト切替なし）。色の決め方を2層に分けている。

- **UIクローム**（筐体のレール・グロー・見出し・リンク）はフルネオン。
  チャートのマークではないので WCAG コントラストだけを満たせばよい。
  本文 15.5:1 / 補足 6.2:1 / シアン 11.6:1 / マゼンタ 5.7:1。
- **チャートのマーク**（折れ線・スカイラインのビル・しきい値線）は
  ダークモードの明度バンド（OKLCH L 0.48–0.67）内に収め、CVD 分離・彩度下限・
  対地コントラストの検証を通した値だけを使う。発光感は色ではなく CSS の
  グローで出す。ネオン原色をそのままマークに使うと明度が揃いすぎて、
  2型色覚で緑と赤が潰れる（検証で ΔE 2.5 まで落ちた）。

検証結果（背景 `#070b14`）:

| セット | 最悪CVD ΔE | 通常視 ΔE | 判定 |
|---|---|---|---|
| チャート4色（系列＋しきい値3色・隣接） | 9.4 | 21.7 | PASS |
| ステータス3色（全ペア） | 9.4 | 21.7 | PASS |
| スカイライン2色（全ペア） | 7.8 | 34.7 | PASS（6–8帯のため直接ラベル必須）|

しきい値は色だけに意味を持たせず、記号（🟢🟡🔴）とラベルと y 軸上の位置を
併記する。スカイラインも各ビルに銘柄名を直接ラベルする。
`prefers-reduced-motion` が有効な環境では点滅カーソルと走査線を出さない。

## スカイライン

保有銘柄の時価を高さにしたビル群（`skyline.py`）。見た目は都市だが、
エンコードは素直な棒グラフのまま:

- 高さは時価に**線形**比例し、必ず 0 を基準にする。平方根などで圧縮すると
  見栄えは整うが量の比較が嘘になるため使わない。
- 窓の点灯は銘柄コードから決定的に導く（FNV-1a）。乱数だと再実行のたびに
  街並みが変わり、データが変わっていないのに画面が動いてしまう。
- Streamlit は生HTMLをサニタイズするため、SVG は data URI の `<img>` として渡す。
